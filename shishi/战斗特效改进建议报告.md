# 苍穹战纪 — 战斗特效改进建议报告

> 基于对 `battle.vue`（6608行，~70个@keyframes）和 `gameStore.ts`（13202行，7种特效状态机）的完整代码审阅。

---

## 一、现有系统概况

| 维度 | 现状 |
|------|------|
| 渲染方式 | 纯 CSS 动画 + Vue 响应式 DOM，无 Canvas/WebGL |
| 动画数量 | ~70 个 `@keyframes` 定义 |
| 特效种类 | 技能光效、受击闪白、粒子飞溅、投射物、飘字、死亡特效、召唤、蓄力、移动轨迹、状态施加、地形痕迹，共 11 类 |
| 清理机制 | `skillEffects` 有批量定时器（300ms间隔）；其余 7 种各自用 `setTimeout` 单独清理 |
| 已有优化 | AOE 大范围跳格、中范围减粒子、AOE/陷阵/轰炸隐藏图标 |
| 性能隐患 | 无 `will-change`、无 `contain`、7种独立定时器、`filter: brightness/blur` 大量用于动画、`box-shadow` 多层叠加在动画元素上 |

## 二、观赏性提升建议（6项）

### ① 地图级震屏效果

**问题**：当前只有被攻击的角色/建筑本身抖动（`triggerShake` 300ms），缺乏"重击"的冲击感。AOE 爆炸、高伤害技能、击杀等大事件没有地图级反馈。

**改进**：在 `battle-map` 容器上添加一个短暂的震屏 class。

```css
/* battle.vue <style> 中添加 */
@keyframes screen-shake {
  0%, 100% { transform: translate(0, 0); }
  20% { transform: translate(-3rpx, 2rpx); }
  40% { transform: translate(3rpx, -2rpx); }
  60% { transform: translate(-2rpx, -1rpx); }
  80% { transform: translate(2rpx, 1rpx); }
}

.battle-map.screen-shaking {
  animation: screen-shake 0.15s ease-out;
}
```

```typescript
// gameStore.ts 中添加
const isScreenShaking = ref(false)
let screenShakeTimer: ReturnType<typeof setTimeout> | null = null

function triggerScreenShake(intensity: 'light' | 'heavy' = 'light') {
  // heavy: 大AOE/击杀；light: 普通命中
  isScreenShaking.value = true
  if (screenShakeTimer) clearTimeout(screenShakeTimer)
  screenShakeTimer = setTimeout(() => {
    isScreenShaking.value = false
  }, intensity === 'heavy' ? 200 : 150)
}
```

```html
<!-- battle.vue 模板中，battle-map 添加 -->
<view class="battle-map" :class="{ 'screen-shaking': gameStore.isScreenShaking }" :style="mapStyle">
```

**触发时机**：
- `triggerHitSpark` 中，若伤害 > 目标最大生命 30% → `triggerScreenShake('heavy')`
- `triggerAOEEffects` 中，若 areaRange >= 2 → `triggerScreenShake('heavy')`
- `handleTargetDefeated` 中 → `triggerScreenShake('heavy')`
- 普通攻击命中 → `triggerScreenShake('light')`

**性能影响**：极低。仅对单个 DOM 元素（`battle-map`）做 150ms transform 动画，transform 走 GPU 合成层，不触发布局/重绘。

### ③ 命中定格（Hit-Stop）

**问题**：攻击命中时所有动画照常播放，缺乏"打击感"的核心要素——命中瞬间的时间停顿。这是格斗游戏/动作游戏提升打击感最有效的手段之一。

**改进**：重击命中时，给 `battle-map` 添加一个极短暂的 `animation-play-state: paused`：

```css
.battle-map.hit-stop {
  animation: hit-stop-fade 0.08s steps(1) forwards;
}

@keyframes hit-stop-fade {
  0% { filter: brightness(1.5) saturate(0.5); }
  100% { filter: brightness(1) saturate(1); }
}
```

```typescript
// gameStore.ts
const isHitStop = ref(false)
let hitStopTimer: ReturnType<typeof setTimeout> | null = null

function triggerHitStop(duration: number = 80) {
  isHitStop.value = true
  if (hitStopTimer) clearTimeout(hitStopTimer)
  hitStopTimer = setTimeout(() => {
    isHitStop.value = false
  }, duration)
}
```

**触发时机**：仅在 `critLevel === 'heavy'` 时触发，即大伤害命中。定格 80ms。

**性能影响**：极低。80ms 的 brightness 滤镜变化，且只在偶发的大伤害时触发。可以配合震屏同时使用。

**注意**：不建议用 `animation-play-state: paused` 暂停所有子动画（这会导致大量动画重新计算），而是用一个短暂的 brightness 闪烁来模拟"定格"感。

### ⑤ 投射物拖尾粒子

**问题**：投射物的尾迹（`projectile-trail`）是一个静态渐变矩形，飞行过程中没有动态拖尾粒子，看起来像一条线而非"能量弹"。

**改进**：在投射物飞行过程中，每隔一定距离生成 1 个淡出粒子。严格限制数量（每个投射物最多 3 个）。

```typescript
// gameStore.ts triggerProjectile 中
function triggerProjectile(fromRow: number, fromCol: number, toRow: number, toCol: number, type: Projectile['type'], attribute: Attribute = 'normal') {
  const color = ATTRIBUTE_CONFIG[attribute]?.color || '#eaeaea'
  const id = `proj_${Date.now()}_${Math.random().toString(36).substr(2, 6)}`
  const duration = Math.max(200, Math.abs(toRow - fromRow) * 80 + Math.abs(toCol - fromCol) * 80)
  
  projectiles.value.push({ id, fromRow, fromCol, toRow, toCol, type, color, duration, timestamp: Date.now() })
  
  // 新增：生成拖尾粒子（最多3个，沿路径分布）
  const trailCount = Math.min(3, Math.max(1, Math.floor(duration / 100)))
  for (let i = 1; i <= trailCount; i++) {
    const t = i / (trailCount + 1)
    const r = fromRow + (toRow - fromRow) * t
    const c = fromCol + (toCol - fromCol) * t
    const trailId = `projtrail_${Date.now()}_${i}_${Math.random().toString(36).substr(2, 4)}`
    trailParticles.value.push({
      id: trailId, row: r, col: c, color, timestamp: Date.now() + i * 60, attribute, size: 'small'
    })
    setTimeout(() => {
      const idx = trailParticles.value.findIndex(p => p.id === trailId)
      if (idx !== -1) trailParticles.value.splice(idx, 1)
    }, 800)
  }
  
  setTimeout(() => {
    const idx = projectiles.value.findIndex(p => p.id === id)
    if (idx !== -1) projectiles.value.splice(idx, 1)
  }, 600)
}
```

**性能影响**：低。每个投射物额外 3 个 small 粒子（40rpx），复用已有的 `trailParticles` 层和 `trail-particle-fade` 动画，无需新增 DOM 层。

## 三、性能优化建议（4项，防止卡顿）

### ⑦ 添加 `will-change` GPU 合成层提示

**问题**：当前所有动画元素都没有声明 `will-change`，浏览器无法提前将它们提升为独立的 GPU 合成层，导致 `transform` 和 `opacity` 动画可能触发重绘而非合成层移动。

**改进**：为所有特效层和动画元素添加 `will-change`：

```css
/* 特效图层 */
.skill-effects-layer,
.floating-texts-layer,
.projectiles-layer,
.hit-sparks-layer,
.death-effects-layer,
.summon-effects-layer,
.move-trail-layer,
.trail-particles-layer,
.charge-effects-layer,
.status-apply-layer,
.terrain-marks-layer {
  will-change: transform;
  contain: layout style paint;  /* 同时添加 contain，见下一条 */
}

/* 动画元素本身 */
.skill-effect,
.floating-text,
.projectile,
.hit-spark,
.death-effect,
.summon-effect,
.charge-effect,
.trail-particle,
.move-trail-particle,
.status-apply-effect {
  will-change: transform, opacity;
}

/* 地图容器（配合震屏） */
.battle-map {
  will-change: transform;
}
```

**注意**：`will-change` 应在元素即将动画时添加、动画结束后移除，但对于这些短生命周期的特效元素，直接在 CSS 中声明即可（它们存在时就在动画）。

**性能影响**：正面。将动画从主线程重绘移至 GPU 合成层，是最高性价比的动画性能优化。

---

### ⑧ CSS `contain` 隔离重绘范围

**问题**：特效层使用 `overflow: visible`，一个特效的动画可能触发整个 `battle-map` 区域的重绘计算。11 个特效层叠加在一起，任何一层的动画都可能影响其他层。

**改进**：为每个特效层添加 CSS containment：

```css
.skill-effects-layer,
.floating-texts-layer,
.projectiles-layer,
.hit-sparks-layer,
.death-effects-layer,
.summon-effects-layer,
.move-trail-layer,
.trail-particles-layer,
.charge-effects-layer,
.status-apply-layer,
.terrain-marks-layer {
  contain: layout style paint;
  /* 注意：不能用 contain: strict，因为需要 overflow: visible 让特效超出格子边界 */
}
```

`contain: layout` — 该层内部的布局变化不影响外部
`contain: style` — 隔离 CSS 计数器和引号
`contain: paint` — 该层的绘制不会超出其边界（但子元素可以 overflow:visible 超出）

**性能影响**：正面。显著减少浏览器在每帧动画时需要计算的重绘区域。当 30+ 个特效同时动画时，contain 可以将重绘范围限制在各层内部。

### ⑨ 统一清理机制 + 特效数量分级

**问题**：当前 7 种特效（`hitFlashTargets`、`defeatRecords`、`trailParticles`、`chargeEffects`、`deathEffects`、`projectiles`、`statusApplyEffects`、`summonEffects`、`moveTrailEffects`、`hitSparkEffects`、`floatingTexts`）各自用独立的 `setTimeout` 清理。当 AOE 命中 10 个目标时，会同时创建：
- 10 个 shake setTimeout
- 10 个 hitFlash setTimeout（每个内部还触发 hitSpark = +10 个）
- 10 个 floatingText setTimeout
- 10 个 hitSpark setTimeout
- 若干 skillEffect（已有批量清理）
- 若干 deathEffect setTimeout

即一次 AOE 可能产生 40-50 个 setTimeout，这些定时器本身的开销不可忽视。

**改进**：将所有特效的清理统一到 `cleanupExpiredEffects` 中：

```typescript
function cleanupExpiredEffects() {
  const now = Date.now()
  
  // skillEffects（已有）
  skillEffects.value = skillEffects.value.filter(e => now - e.timestamp < 1700)
  
  // 新增：统一清理其他特效
  floatingTexts.value = floatingTexts.value.filter(t => now - t.timestamp < 1200)
  hitFlashTargets.value = hitFlashTargets.value.filter(t => now - t.timestamp < 400)
  defeatRecords.value = defeatRecords.value.filter(d => now - d.timestamp < 1500)
  trailParticles.value = trailParticles.value.filter(p => now - p.timestamp < 1800)
  chargeEffects.value = chargeEffects.value.filter(e => now - e.timestamp < 800)
  deathEffects.value = deathEffects.value.filter(d => now - d.timestamp < 1600)
  projectiles.value = projectiles.value.filter(p => now - p.timestamp < 600)
  statusApplyEffects.value = statusApplyEffects.value.filter(s => now - s.timestamp < 1200)
  summonEffects.value = summonEffects.value.filter(s => now - s.timestamp < 1500)
  moveTrailEffects.value = moveTrailEffects.value.filter(t => now - t.timestamp < 600)
  hitSparkEffects.value = hitSparkEffects.value.filter(s => now - s.timestamp < 500)
  shakingTargets.value = shakingTargets.value.filter(t => now - t.timestamp < 300)
  
  // 全部清空后停止定时器
  const totalEffects = skillEffects.value.length + floatingTexts.value.length + 
    hitFlashTargets.value.length + defeatRecords.value.length + 
    trailParticles.value.length + chargeEffects.value.length + 
    deathEffects.value.length + projectiles.value.length + 
    statusApplyEffects.value.length + summonEffects.value.length + 
    moveTrailEffects.value.length + hitSparkEffects.value.length + 
    shakingTargets.value.length
  
  if (totalEffects === 0 && effectCleanupTimer) {
    clearInterval(effectCleanupTimer)
    effectCleanupTimer = null
  }
}
```

同时移除各 `trigger*` 函数中的 `setTimeout` 清理代码。

**特效数量分级**（在 `cleanupExpiredEffects` 或渲染层添加）：

**性能影响**：显著正面。将 40-50 个 setTimeout 合并为 1 个 300ms 间隔的 setInterval，减少定时器开销；特效超限时自动减少粒子数，防止 DOM 爆炸。

### ⑩ 减少 `filter` 和多层 `box-shadow` 在动画中的使用

**问题**：当前多处动画使用了 `filter: brightness()` 和 `filter: blur()`，以及多层 `box-shadow`：

| 位置 | 问题属性 | 行号 |
|------|----------|------|
| `.core-fire` | `box-shadow: 0 0 45rpx, 0 0 90rpx, 0 0 135rpx`（3层） | 3548 |
| `fire-burn` 动画 | `filter: brightness(1.5)` | 3560 |
| `defeat-kill` 动画 | `filter: brightness(3), brightness(2), brightness(1.5), brightness(0.5)` | 5671-5677 |
| `defeat-self` 动画 | `filter: brightness(1.5) blur(2rpx), brightness(1.3) blur(4rpx), blur(6rpx), blur(10rpx)` | 5680-5685 |
| `self-defeat-dissolve` | `filter: blur(2rpx), blur(6rpx)` | 5723-5726 |
| `hit-flash-brightness` | `filter: brightness(3) saturate(1.5), brightness(2) saturate(1.2)` | 5623-5628 |
| `core-line-pierce` | `filter: brightness(2)` | 5607 |
| `core-bomb-detonate` | `filter: brightness(2.5)` | 5618 |

`filter` 属性在动画中的代价远高于 `transform` 和 `opacity`——它需要在每一帧重新计算像素。`box-shadow` 多层叠加在动画元素上也会导致大面积重绘。

**改进方案**：

1. **`filter: brightness()` → 用 `opacity` 叠加白色背景替代**：
```css
/* 替代 hit-flash-brightness 中的 filter */
@keyframes hit-flash-brightness {
  0% { opacity: 1; }
  20% { opacity: 0.4; }  /* 配合 ::after 白色覆盖层实现"闪白" */
  50% { opacity: 0.7; }
  100% { opacity: 1; }
}
/* 现有的 ::after 白色覆盖层已经存在（hit-flash-white），只需调整配合 */
```

2. **`filter: blur()` → 仅在非动画状态或动画末尾使用**：
```css
/* defeat-self 最后一帧才有 blur，中间帧用 opacity + scale 模拟 */
@keyframes defeat-self {
  0% { transform: scale(1); opacity: 1; }
  30% { transform: scale(1.1); opacity: 0.8; }
  60% { transform: scale(0.8); opacity: 0.4; }
  100% { transform: scale(0.5); opacity: 0; filter: blur(8rpx); }  /* 仅最后一帧 */
}
```

3. **多层 `box-shadow` → 减少层数**：
```css
/* 替代前 */
.core-fire { box-shadow: 0 0 45rpx #ff6b35, 0 0 90rpx #ff0000, 0 0 135rpx rgba(255, 0, 0, 0.5); }
/* 替代后（2层足够） */
.core-fire { box-shadow: 0 0 50rpx #ff6b35, 0 0 100rpx rgba(255, 0, 0, 0.4); }
```

4. **用 `::before/::after` 伪元素 + `opacity` 替代 `filter: brightness`**：
```css
/* 核心思路：用白色半透明覆盖层的 opacity 动画替代 brightness 滤镜 */
.skill-effect .effect-core::after {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: 50%;
  background: rgba(255, 255, 255, 0.6);
  opacity: 0;
  animation: core-flash 0.3s ease-out;
}
@keyframes core-flash {
  0% { opacity: 0.8; }
  100% { opacity: 0; }
}
```

**性能影响**：显著正面。`filter` 是 CSS 动画中代价最高的属性之一，移除后帧率提升明显。特别是在低性能设备上（uni-app 移动端），`filter: blur()` 在动画中间帧会导致严重掉帧。

## 四、附加建议（低成本，锦上添花）

### ⑪ 天气特效限制可见区域

**问题**：雪地（❄️）、火焰（🔥）、迷雾（4个cloud-puff）的 `infinite` 动画在所有对应格子持续运行。如果地图有 50 个雪地格子，就有 50 个 `snowflake` 无限循环动画在跑。

**改进**：利用 `scroll-view` 的可视区域，只渲染可见区域的天气特效。或者更简单——将天气动画频率降低：

```css
/* 降低天气动画频率 */
.snow-icon { animation: snowflake 3s infinite ease-in-out; }  /* 2s → 3s */
.fire-icon { animation: fire 1.2s infinite ease-in-out; }    /* 0.8s → 1.2s */
.cloud-puff { animation: cloudFloat 4s infinite ease-in-out; } /* 3s → 4s */
```

### ⑫ 技能光效动画时长微调

当前大部分特效动画为 0.8-1.2s，在移动端可能感觉偏慢。建议将核心爆发类动画缩短：

| 动画 | 当前时长 | 建议时长 | 理由 |
|------|----------|----------|------|
| `base-pulse` | 1.0s | 0.7s | 底层光晕不需要那么久 |
| `core-pulse` | 0.8s | 0.6s | 核心爆发要快才有力 |
| `ring-expand` | 1.0s | 0.7s | 扩散环快速消失更有冲击感 |
| `wave-expand` | 1.2s | 0.8s | 二次波纹太慢会拖沓 |
| `float-up` | 1.2s | 1.0s | 飘字停留过久会遮挡视野 |

这将使战斗节奏更紧凑，同时减少同时存在的特效数量（因为清理更快）。

### ⑬ 重复 keyframes 合并

当前有大量结构几乎相同的 keyframes（都是 `scale(0.3)→scale(1.x)→scale(1)` + `opacity: 1→0`），可以提取为参数化的通用动画：

```css
/* 通用：缩放爆发后消散 */
@keyframes burst-fade {
  0% { transform: translate(-50%, -50%) scale(var(--start-scale, 0.3)); opacity: 1; }
  50% { transform: translate(-50%, -50%) scale(var(--peak-scale, 1.3)); opacity: var(--peak-opacity, 0.7); }
  100% { transform: translate(-50%, -50%) scale(var(--end-scale, 1)); opacity: 0; }
}
```

这不影响运行性能，但可以减小 CSS 文件体积（当前 battle.vue 有 6608 行，样式部分占 3800+ 行）。
